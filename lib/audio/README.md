# 随机音频事件的曲库

往这个目录里放音频文件，然后在同级的 `lib/audio-tracks.json` 里登记。

## 怎么加一首

1. 把文件拷进本目录，文件名只用**字母、数字、下划线、横杠**，扩展名 `.ogg` 或 `.mp3`。
   （含空格、中文、括号的文件名会被静默忽略 —— 白名单与宿主 HTTP 路由是同一套规则。）
2. 在 `lib/audio-tracks.json` 里加一条：

```json
[
  { "file": "morning-loop.mp3", "title": "早八的电梯" }
]
```

`title` 只用来在日志里说明播了什么，可以不写（不写就用文件名）。

## 「只要高潮部分」怎么切

用户要求「音质不用好，重点是把高潮放出来」。剪切命令（需要 ffmpeg）：

```bash
ffmpeg -i 原文件.m4a -ss 100 -to 142 -c:a libvorbis -q:a 4 -ac 2 -ar 44100 out.ogg
```

- `-ss 100 -to 142` 是秒，`-ss` 放在 `-i` 后面是**精确定位**（慢但准），
  放前面快但会落在最近的关键帧上。
- `-q:a 4` 是 Vorbis 质量档（0~10，4 约等于 128 kbps）。用户明确说过音质不重要，
  所以没必要上 `-q:a 6` —— 42 秒副歌在 q4 是 632 KB，q6 会到 1 MB 以上。
- **先看波形再定 `-ss`**，别凭记忆猜时间。现成工具：`tools/.loudest.mjs`
  （解 PCM 自己按固定秒数分桶算 RMS，标出超过均值 +1.5 dB 的段）。
  隔壁 `tools/.fetch-bv.mjs` 负责从 B 站抓官方 MV 的音频流（见其文件头注释）。

## 只放高潮不放全曲，是刻意的

随机事件不该让用户等 3 分钟才听到想听的部分，也不该在用户已经切走注意力后
还在响。42 秒副歌是「刚觉得好听就结束」的长度 —— 留一点「还想听」的余味，
但不会烦。

## 空清单会发生什么

`audio-tracks.json` 是 `[]` 时，**这条随机事件整个不存在**：它不会参与抽取，
也不会占掉一份命中率（详见 `lib/index.js` 里 `buildEvents()` 末尾的注释）。
所以清单可以一直空着，不影响其他事件。

## 为什么不放在 sounds/

`lib/sounds/` 是随包发布的挖掘音效，文件名写死在 `lib/client.js` 的 `SOUND_FILES` 里，
由 `/dsh-lucky-block/sound` 路由用「只认 `.ogg`」的白名单发出。
本目录走的是另一条路由 `/dsh-lucky-block/audio`，允许 `.mp3`，
两者互不影响 —— 改这边的白名单不会放松挖掘音效那边。
