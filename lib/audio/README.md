# 随机音频事件的曲库

往这个目录里放音频文件，然后在同级的 `lib/audio-tracks.json` 里登记。

## 怎么加一首

1. 把文件拷进本目录，文件名只用**字母、数字、下划线、横杠**，扩展名 `.ogg` 或 `.mp3`。
   （含空格、中文、括号的文件名会被静默忽略 —— 白名单与宿主 HTTP 路由是同一套规则。）
2. 在 `lib/audio-tracks.json` 里加一条：

```json
[
  { "file": "morning-loop.mp3", "title": "早八的电梯" }
]
```

`title` 只用来在设置面板和日志里说明播了什么，可以不写（不写就用文件名）。

## 一首歌 = 一条事件

登记几条就有几条随机事件，id 由文件名派生：`morning-loop.mp3` → `audio-morning-loop`。
所以**每首歌能单独开关**（设置面板里取消勾选，或 `config.json` 的 `events` 里写
`"audio-morning-loop": { "enabled": false }`）。

每首歌的权重固定是 1。想让它更容易被抽到，在面板里调高权重即可。

## 「只要高潮部分」怎么切

用户要求「音质不用好，重点是把高潮放出来」。剪切命令（需要 ffmpeg）：

```bash
ffmpeg -i 原文件.m4a -ss 58 -to 95 -c:a libvorbis -q:a 4 -ac 2 -ar 44100 out.ogg
```

- `-ss 58 -to 95` 是秒，`-ss` 放在 `-i` 后面是**精确定位**（慢但准），
  放前面快但会落在最近的关键帧上。
- `-q:a 4` 是 Vorbis 质量档（0~10，4 约等于 120 kbps）。用户明确说过音质不重要，
  所以没必要上 `-q:a 6` —— 37 秒在 q4 是 575 KB，q6 会到 1 MB 以上。
- **先看波形再定 `-ss`**，别凭记忆猜时间。现成工具：`tools/.loudest.mjs`
  （解 PCM 自己按固定秒数分桶算 RMS，标出超过均值 +1.5 dB 的段）。
  隔壁 `tools/.fetch-bv.mjs` 负责从 B 站抓音频流（见其文件头注释）。

## 现在包里的三首

| 文件 | 时长 | 切法 |
| --- | --- | --- |
| `never-give-you-up.ogg` | 42 秒 | 原曲副歌整段 |
| `stay-at-your-house.ogg` | 37 秒 | 58–95 秒（全曲唯一持续 -9 dB 的副歌） |
| `my-shot-satisfied.ogg` | 54 秒 | 1–55 秒（源视频 57 秒，几乎整段都是高潮） |

## 只放高潮不放全曲，是刻意的

随机事件不该让用户等三四分钟才听到想听的部分，也不该在用户已经切走注意力后
还在响。40 秒上下是「刚觉得好听就结束」的长度 —— 留一点「还想听」的余味，
但不会烦。

## 空清单会发生什么

`audio-tracks.json` 是 `[]` 时，**这一类随机事件整个不存在**：`audioEvents()`
返回空数组，没有任何 `audio-*` 条目参与抽取，也不占命中率。
所以清单可以一直空着，不影响其他事件。

## 为什么不放在 sounds/

`lib/sounds/` 是随包发布的挖掘音效，文件名写死在 `lib/client.js` 的 `SOUND_FILES` 里，
由 `/dsh-lucky-block/sound` 路由用「只认 `.ogg`」的白名单发出。
本目录走的是另一条路由 `/dsh-lucky-block/audio`，允许 `.mp3`，
两者互不影响 —— 改这边的白名单不会放松挖掘音效那边。
