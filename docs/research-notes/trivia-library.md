> 用途：`dsh-lucky-block` 的零 token「冷知识」事件。随机抽一条直接显示给用户，
> **不调用任何模型、不联网**。

> 数据文件：[`lib/trivia-data.json`](../lib/trivia-data.json)（**435 条**）

   [`research/build-final.mjs`](build-final.mjs) 的 `seeds` 数组首位，合并时**种子优先入档**，
   确保不会被近似条目挤掉。
2. 新增 173 条候选（[`research/trivia-candidates.mjs`](trivia-candidates.mjs) 的 `candidates`），

   装配脚本输出的确定性结果：**20 条种子 + 415 条原有条目 + 173 条候选 = 608 条**

## 1. 准确性怎么保证

先诚实地说明检索工具的真实表现，不夸大：

- **本轮检索质量依然很差。** `research` 返回的多是 SEO 垃圾站；
  `web_fetch` 抓中文维基百科报 `EAI_AGAIN`（DNS 解析失败）。
  因此**没有一条条目是靠「搜到一句话就照抄」写出来的**。

改用三条互相独立的策略：

1. **只收教科书级、可被任何一本权威教材或教科书式参考源印证的事实。**
   凡是需要「某个冷门论文里恰好写过」才成立的，一律不收。
   `source` 字段因此多为「公开常识（植物学）」这种**学科标注**而非虚构的文献名——
   宁可标得朴素，也不编造一个看起来精确却查不到的出处。
2. **记不准的数字一律不写，或写成量级。**
   例如蚂蚁总重量与人类相当这条，用「大致相当 / 数量级」表述，
   不去坐实一个查不到的年吞吐量。凡是「某研究说 N%」而拿不到原研究的，直接不写。
3. **有争议的条目，把争议写进正文，而不是假装它是定论。**
   例如埃斯库罗斯被乌龟砸死一条，正文里明写「据传」，
   `source` 标为「古典文献记载，真实性存疑」。

此外本轮**主动做了三次否决**，否决过程本身就是准确性策略的一部分：

- 候选「圆周率中包含了所有人的生日」：核实后发现 **π 是否「正规数」至今未被证明**，
  Scientific American 明确指出数学家无法证明 π 是正规数，甚至不知道其中任一数字
  是否出现无穷多次。这条把猜想当成事实，**剔除**。
- 候选「人体每秒发生约一万次天然放射性衰变」：文献中常被引用的量级是
  **每秒约 4400 次**（主要来自体内的钾-40），原数字既无来源又与常见量级不符，**剔除**。
- 候选「枕头用久了会变重」：流传极广，但增重来源缺乏可控研究支撑，属于难以核查的经验之谈，**剔除**。

## 4. 维护须知

- **`source` 字段不展示给用户**，只用于事后核查，所以它可以写「公开常识（植物学）」这类朴素标注。
- 文件必须是 **UTF-8 无 BOM**。`fs.writeFileSync(..., {encoding:'utf8'})` 是安全的；
  **不要**用 PowerShell 的 `Set-Content -Encoding UTF8`（会写 BOM，`JSON.parse` 直接失败）。
- **不要**用 PowerShell 的 `>` 重定向读/写中文，会变成 UTF-16；读文件请用 read 工具。
- 继续扩充时，请走脚本（[`research/build-final.mjs`](build-final.mjs) 的校验会拦住
  非法 `topic`、越界长度、换行、Markdown 字符、重复条目），**不要手改 JSON**。
- 新条目入档前先跑一次 2-gram 语义去重（阈值 0.55），避免「意思重复但措辞不同」的漏网。
